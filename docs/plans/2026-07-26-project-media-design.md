# 工程全过程影像板块设计

## 目标

为每个工程提供按六个既有阶段和拍摄日期归档的照片、视频记录，使现场上传、项目内复盘和跨项目检索保持同一套数据、权限、备份与回滚链路。

## 已确认需求

- 影像必须关联具体工程。
- 影像必须选择六个工程阶段之一。
- 影像必须填写拍摄日期。
- 完成开发后先进行全项目代码审核和修复。
- 用户完成本地预览确认后，才进入群晖部署。

## 位置方案

### 方案 A：新增左侧一级菜单“工程影像”

优点是入口醒目；缺点是上传时还要二次选择工程，并与“工程项目”“工程档案”形成第三套资料入口，容易关联错项目。

### 方案 B：只在“工程档案”增加影像分类

优点是改动较小；缺点是现场人员难以在工程上下文中快速上传，六阶段进度与影像记录被割裂。

### 方案 C：工程详情主入口＋工程档案全局检索

在具体工程详情页增加“全过程影像”页签，作为上传、阶段浏览和时间轴浏览的主入口；同时在“工程档案”增加“过程影像”分类，作为跨工程检索入口。

**采用方案 C。** 它兼顾现场录入与档案查阅，并复用既有项目权限、档案持久化、上传保护、备份恢复和回滚机制。

## 信息架构

工程详情页顶部使用两个稳定页签：

```text
┌──────────────────────────────────────────────┐
│ 工程名称 / 工程编号                           │
│ [执行流程] [全过程影像 26]                    │
├──────────────────────────────────────────────┤
│ 全部  前期  生产  施工  调试  验收  结算       │
├──────────────────────────────────────────────┤
│ 2026-07-26                                   │
│ [照片] [照片] [视频] [照片]                   │
│ 2026-07-25                                   │
│ [视频] [照片]                                │
└──────────────────────────────────────────────┘
```

- “执行流程”保留当前工程概览、路线图和任务节点。
- “全过程影像”默认显示全部阶段，按拍摄日期倒序分组。
- 六阶段筛选顺序与现有工程流程完全一致：
  1. 前期对接 & 设计
  2. 生产准备
  3. 进场施工
  4. 安装调试
  5. 验收交付
  6. 结算收尾
- 支持照片/视频类型筛选和标题搜索。
- 空状态直接说明如何上传第一批现场影像。

## 上传流程

- 工程上下文自动锁定，不允许在上传弹窗中改到其他工程。
- 必填：工程阶段、拍摄日期、至少一个照片或视频文件。
- 选填：本批记录说明。
- 支持同一阶段、同一天批量选择多个文件。
- 每个文件独立上传并生成一条档案记录；部分失败时明确列出失败文件，已成功文件不重复上传。
- 文件类型沿用服务端白名单：
  - 图片：PNG、JPG/JPEG、GIF、WEBP
  - 视频：MP4、MOV、WEBM
- 单文件上限继续由服务端 `UPLOAD_MAX_BYTES` 统一控制，界面显示实际限制，避免前后端口径不一致。

## 数据设计

继续使用 `archives` 资源，新增档案分类 `Media`，并为 `ArchiveItem` 增加可选影像元数据：

- `mediaPhase`：六阶段之一；`Media` 分类时必填。
- `capturedAt`：拍摄日期，使用本地日期字符串 `YYYY-MM-DD`；`Media` 分类时必填。
- `mediaType`：`image` 或 `video`。
- `description`：本批记录说明。

既有档案记录无需迁移。项目内影像只读取 `category === 'Media'` 的记录；工程档案继续读取全部记录。

## 视觉方向

- 沿用现有 iERP 的蓝色主色、深色模式、圆角卡片和中文无衬线字体，避免新板块像独立产品。
- 结构签名采用“六阶段胶片时间轴”：阶段编号是真实施工顺序，不作为装饰。
- 影像卡片本身保持克制，优先显示现场内容；视频叠加播放标识和时长容器。
- 桌面端使用响应式网格，移动端使用两列缩略图和横向阶段选择。
- 所有交互提供键盘焦点；预览层支持关闭、上一项、下一项；遵守减少动态效果设置。

## 预览与删除

- 图片使用原图适应容器预览。
- MP4、MOV、WEBM 使用原生视频控件；浏览器不支持解码时提供下载。
- 全屏预览展示阶段、日期、上传人和说明。
- 删除沿用现有受保护删除流程和权限判断，不绕过回收站、资源权限或文件引用保护。

## 安全与权限

- 上传仍通过已认证的 `/api/upload`，不接受客户端伪造文件类型。
- 档案创建、读取、删除继续经过 `archives` 项目范围权限策略。
- 服务端在创建/更新 `Media` 档案时验证项目、阶段、日期、媒体类型与 URL 格式。
- 页面不使用不安全 HTML，不在浏览器持久化敏感数据。
- 预览只使用受保护上传 URL；下载继续使用现有鉴权路径。

## 验收标准

- 每个可见工程都能打开“全过程影像”页签。
- 每条影像记录均有阶段和拍摄日期。
- 可批量上传受支持图片/视频，拒绝非法类型和超限文件。
- 可按阶段、日期、文件类型和标题查阅。
- 图片与受浏览器支持的视频可以在线预览。
- “工程档案”可按“过程影像”检索同一批记录。
- 不破坏既有任务附件和其他档案。
- 新增单元/API/前端测试通过，全量测试、TypeScript 构建、依赖审计、发布检查和代码差异检查通过。
- 本地预览经用户确认后才允许群晖部署。
