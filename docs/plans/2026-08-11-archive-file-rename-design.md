# 工程档案文件重命名设计

日期：2026-08-11

## 目标

- 工程档案的上传人和默认超级管理员可以修改文件显示名称。
- 只允许修改文件主体名，扩展名由原始存储文件锁定。
- 修改后的名称用于列表、搜索、导出、预览标题和下载文件名。
- 不移动或重命名磁盘上的 UUID 文件，不改变档案 URL、类型和其他元数据。

## 方案

1. 新增专用接口 `PATCH /archives/:id/name`，请求体仅包含 `title`。
2. 服务端从数据库读取原档案，仅允许 `uploader === 当前用户昵称` 或
   `isDefaultAdmin === true` 的用户重命名；新档案同时保存稳定的 `uploaderId`，
   历史档案首次由原上传人重命名时自动补齐。
3. 文件主体名去除首尾空白，长度限制为 1 至 200 个字符，并拒绝控制字符、
   Windows 非法文件名字符和尾部的点或空格。
4. 服务端只替换 `title`，其他字段全部继承原记录，并触发现有记录更新通知。
5. 工程档案列表为有权限的用户显示编辑图标；弹窗把扩展名作为只读后缀展示。
6. 下载地址增加 `archiveId`。服务端验证档案存在、当前用户可读且档案 URL 与
   请求文件一致后，以“当前标题 + 原扩展名”生成下载文件名。

## 安全边界

- 客户端只控制主体名，不能提交存储路径或扩展名。
- 服务端不信任客户端传入的下载名称。
- 通用档案更新接口禁止改写存储 URL 和文件类型，避免扩展名旁路。
- CSV 导出对公式起始字符加文本前缀，并正确转义引号。
- 档案 ID 与文件 URL 不匹配时返回 404，避免通过 ID 探测其他档案。
- 旧下载链接继续可用，未提供 `archiveId` 时保持 UUID 下载名，确保兼容性。

## 验证

- API 权限：上传人、默认超级管理员成功；其他用户和普通管理员失败。
- API 校验：空名称、过长名称、非法字符失败，其他字段保持不变。
- 下载：匹配档案 ID 时使用新名称和原扩展名；不匹配或不可见时返回 404。
- 前端：权限按钮、固定扩展名、专用 PATCH 接口、列表/搜索/导出/预览传播。
- 全量测试、TypeScript/Vite 构建、依赖审计和发布验证全部通过后部署。
