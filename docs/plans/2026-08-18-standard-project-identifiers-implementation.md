# 工程标识规范实施计划

日期：2026-08-18

## 1. 标识服务与单元测试

- 新增服务端工程标识模块，集中处理北京时间建档年月、UUID v4 和 `YYYY-MM-NNN` 格式。
- 先覆盖年度连续编号、跨月、跨年、人工编号优先、重复编号和不安全输入测试。

## 2. 数据库迁移与年度序列

- 新增年度工程合同序列表，年份唯一、序号非负。
- 根据已有工程 `createdAt` 初始化年度计数，不改写历史工程记录。
- 更新迁移假数据库与顺序契约测试，保证迁移幂等。

## 3. 工程创建接口

- 工程 POST 忽略客户端提交的 `id` 和 `code`，由服务器生成 UUID 与最终工程编号。
- 在同一事务中先取得全局建档锁，再锁定年度序列、检查编号唯一性并写入工程。
- 人工内部管控编号为空时回填自动编号；冲突返回 409。
- 保持现有 RBAC、负责人和资源策略不变。
- 更新工程时由服务端保留内部 UUID、正式工程编号和建档时间，客户端不能篡改。

## 4. 前端创建与展示

- 删除工程创建中的 `Math.random()` ID 和随机 `PJ` 编号。
- 服务器成功返回后再加入工程列表；失败时保留表单。
- 回款详情将“工程 ID”改为“工程编号”，展示 `project.code`。
- 编辑工程时将正式工程编号设为只读；甲方合同编号仍可补录或修改。

## 5. 全面验证

- 运行工程标识、资源 API、迁移和前端契约定向测试。
- 执行 `npm run verify:release` 与 `git diff --check`。
- 确认已有工程数据和关联字段没有迁移或改写代码。
