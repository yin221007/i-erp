# 手机端 PDF 预览修复设计

## 问题

工程档案和回款发票目前用 `iframe` 直接打开 PDF。桌面浏览器通常内置 PDF
查看器，但微信及部分 Android WebView 不提供该能力，因此有效 PDF 也会显示灰屏
或破损文件图标。

## 方案

- 使用随前端发布、同源加载的 PDF.js，在 Canvas 中分页渲染 PDF，不依赖手机系统
  的 PDF 插件，也不使用第三方在线预览服务。
- PDF 组件仅在用户打开 PDF 时动态加载，避免增加首页和普通档案列表的首屏负担。
- 工程档案与回款发票统一复用该组件，提供上一页、下一页、缩放、加载状态、重试和
  清晰的失败提示；原下载入口继续保留。
- PDF.js Worker 由 Vite 打入本地版本化资源，继续受现有 CSP `worker-src 'self'`
  约束。文件读取仍走原 `/api/uploads/:filename` 鉴权接口并携带会话，不新增公开地址。
- 禁止 PDF.js 使用动态求值，降低恶意文档风险；原文件、档案记录、权限和备份结构
  均不修改。

## 验证

- 增加静态回归测试，禁止两个 PDF 入口再次退回原生 `iframe`。
- 用真实 PDF 在桌面和 390px 手机视口验证加载、分页、缩放、关闭与下载入口。
- 运行完整测试、TypeScript/Vite 构建、依赖审计、发布门禁和差异检查。
- 群晖部署继续执行备份、恢复演练、克隆候选、正式切换、公网与回退保护。
