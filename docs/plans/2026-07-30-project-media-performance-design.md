# 全过程影像隔离与加载性能设计

日期：2026-07-30
目标版本：1.12.3

## 目标

1. 全过程照片和视频只在单个工程的“全过程影像”中展示，不进入“工程档案”的分类、列表、统计、搜索、首页档案动态或 CSV 导出。
2. 保留现有 `archives` 表中的 `Media` 记录作为影像持久化数据，不迁移、不删除历史文件。
3. 影像文件夹和相册列表不再直接加载大尺寸原图或视频元数据，明显降低首屏请求量和传输量。
4. 原图、视频的查看、下载、权限校验和删除语义保持不变。

## 方案选择

采用“受保护的按需缩略图缓存 + 前端分批渲染”。

- 后端为已授权的图片上传文件提供缩略图接口。
- 第一次请求时生成指定规格的缩略图并写入可再生缓存，后续直接复用。
- 列表和文件夹封面只请求缩略图；用户打开预览时才请求原图。
- 视频卡片不预加载视频内容或元数据，点击预览后才加载原视频。
- 相册内文件分批渲染，减少一次性 DOM、图片解码和网络请求。

不采用纯前端懒加载，因为它仍会传输大尺寸原图；不采用上传时附加正式缩略图，因为会增加附件数量并且无法覆盖历史影像。

## 后端设计

### 缩略图接口

- 在现有上传文件访问控制之后提供缩略图读取能力，复用原文件的工程可见性和上传人权限。
- 仅允许受支持的图片格式和固定宽度档位，拒绝任意路径、任意尺寸和非图片文件。
- 缩略图以原文件稳定名称、文件状态和宽度生成缓存键，避免覆盖与路径穿越。
- 返回正确的图片 MIME、内容长度、私有长期缓存头和 `X-Content-Type-Options: nosniff`。
- 生成失败时返回明确错误，前端回退到受保护的原图，不影响查看。

### 缩略图缓存

- 缓存放在上传目录下的专用隐藏目录，属于可再生派生数据。
- 备份、附件计数、发布包、上传访问和资源迁移必须排除该目录。
- 删除原上传文件时同步删除对应缩略图；孤立缓存可由既有清理流程安全回收。
- 缓存目录不允许通过普通上传 URL 直接访问。

### 安全与资源限制

- 复用现有登录、资源可见性和受保护上传 URL 校验。
- 固定最大输出宽度、像素量和并发生成数量，防止图片解码耗尽内存。
- 不允许 SVG、PDF、视频或未知格式进入图片处理器。
- 缩略图生成使用受维护的图片处理依赖，并通过依赖审计和群晖真实镜像构建验证。

## 前端设计

### 工程档案隔离

- 建立统一的“常规工程档案”过滤结果，排除 `category === 'Media'`。
- 工程档案分类中移除“过程影像”。
- 列表、项目分组、数量、搜索、排序和 CSV 导出只使用常规工程档案。
- 首页“档案上传”动态排除 `Media`，避免点击后进入不存在的工程档案记录。
- 单工程“全过程影像”继续接收该工程的全部档案数据并自行筛选 `Media`。

### 影像加载

- 图片卡片和文件夹封面使用缩略图 URL，设置 `loading="lazy"` 和 `decoding="async"`。
- 首屏少量封面可正常加载，其余交给浏览器懒加载。
- 视频卡片使用静态视频占位，不设置视频 `src`；预览弹窗打开后才挂载原视频。
- 相册初始只渲染固定数量的媒体卡片，提供“加载更多”；筛选或切换文件夹时重置批次。
- 原图预览仍使用原始受保护 URL，并保持上一项、下一项、下载和删除功能。

## 兼容与数据

- 不修改历史 `Media` 记录，不删除任何照片或视频。
- 历史图片首次打开时自动生成缩略图，因此无需迁移。
- 历史视频显示统一占位图，打开后仍可正常播放。
- 正式附件数量只统计原始上传文件，缩略图缓存不计数。

## 错误处理

- 缩略图请求失败时，单张图片回退原图并避免循环重试。
- 图片本身损坏时显示明确占位，不影响其他卡片。
- 缩略图生成异常只记录脱敏错误，不输出文件内容、账号或路径。
- 缓存写入采用临时文件加原子替换，避免并发请求产生半文件。

## 验证

1. 单元测试：缩略图参数、缓存键、格式白名单、缓存排除和批次逻辑。
2. API 测试：未登录、无权限、合法图片、视频拒绝、路径穿越、缓存命中和删除清理。
3. 前端契约测试：工程档案全面排除 `Media`，图片使用缩略图，视频零预加载，相册分批渲染。
4. 完整门禁：全部测试、TypeScript/Vite 构建、依赖审计、Shell 语法、Compose 契约、发布卫生和 `git diff --check`。
5. 群晖候选环境：真实镜像构建、克隆数据验证、缩略图首次生成与缓存命中、附件计数不变。
6. 正式验收：工程档案无过程影像；全过程影像首屏明显减少原图/视频请求；预览、下载、删除和权限正常；内外网健康、认证和 TLS 正常。

## 发布与回退

- 使用新的不可变 `1.12.3` 运行标签，不覆盖任何 `1.12.2` 镜像。
- 发布前创建升级备份并完成数据库、附件和恢复演练。
- 候选验证通过后再短暂停写并切换；失败时自动回退旧镜像和最终升级快照。
- 缩略图为派生缓存，回退时可直接丢弃或重新生成，不影响业务数据恢复。
